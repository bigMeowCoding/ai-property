# Spec: 手机号验证码登录
type: business

## 1. 需求定义

### 1.1 背景与目标
- 业务背景：当前仅支持账号密码登录，新用户注册成本高，导致流失率偏高
- 用户价值：3 步完成登录，无需记忆密码，降低使用门槛
- 成功指标：登录转化率提升 15%，验证码到达率 > 95%

### 1.2 需求范围（Scope）
- **In-Scope（本次做）：**
  - [ ] 手机号输入与实时格式校验
  - [ ] 验证码获取（60 秒倒计时）
  - [ ] 验证码校验与登录态写入
  - [ ] 登录失败错误提示
- **Out-of-Scope（明确不做）：**
  - [ ] 第三方登录（微信/QQ）
  - [ ] 密码找回/重置功能

### 1.3 需求澄清 / 待确认项（Clarification）

| 序号 | 问题描述 | 当前假设 / 建议方案 | 优先级 |
|------|----------|---------------------|--------|
| Q1 | 验证码有效期多久？ | 建议：5 分钟，错误 3 次后需图形验证码 | 阻塞 |
| Q2 | 支持海外手机号？ | 建议：首期仅支持中国大陆 +86 | 非阻塞 |
| Q3 | 登录态有效期？ | 建议：JWT 7 天，支持自动续期 | 非阻塞 |

## 3. 用户旅程与交互（User Journey & UX）

- **核心路径：** 进入登录页 → 输入手机号 → 点击获取验证码 → 输入验证码 → 点击登录 → 进入首页
- **关键页面/组件：**
  - `PhoneLoginPage`：登录页容器
  - `PhoneInput`：手机号输入（含 +86 前缀）
  - `CodeInput`：验证码输入（含倒计时）
  - `CaptchaModal`：图形验证码弹窗（错误 3 次后触发）
- **异常分支：**
  - 手机号格式错误：输入框实时标红，提示"请输入正确的 11 位手机号"
  - 验证码错误：提示"验证码错误或已过期"，清空验证码输入框
  - 网络超时：Toast 提示"网络异常，请稍后重试"，登录按钮恢复可点击
- **空状态/边界：**
  - 首次进入：手机号输入框自动聚焦
  - 验证码发送失败：按钮恢复可点击，提示具体错误原因

## 4. 业务规则（Business Rules）

| 规则编号 | 触发条件 | 判断逻辑 | 系统行为 |
|----------|----------|----------|----------|
| BR-01 | 用户输入手机号 | 正则：`/^1[3-9]\d{9}$/` | 通过校验，获取验证码按钮可用 |
| BR-02 | 用户点击获取验证码 | 校验手机号格式 | 格式正确则发送验证码，按钮进入 60s 倒计时 |
| BR-03 | 验证码错误次数 ≥ 3 | 累计校验失败次数 | 弹出图形验证码弹窗，校验通过后才可继续 |
| BR-04 | 用户点击登录 | 校验手机号 + 验证码格式 | 格式正确则调用登录 API，按钮进入 loading 态 |
| BR-05 | 登录成功 | API 返回 token | 写入 Pinia + localStorage，跳转首页 |

### 5.2 接口定义

```typescript
// 发送验证码请求
interface SendCodeReq {
  phone: string;      // | 必填 | 正则：/^1[3-9]\d{9}$/ | 示例：13800138000
  captchaToken?: string; // 选填 | 图形验证码校验通过后携带
}

interface SendCodeRes {
  success: boolean;
  message?: string;
  retryAfter?: number; // 剩余冷却时间（秒）
}

// 验证码登录请求
interface PhoneLoginReq {
  phone: string;  // | 必填 | 正则：/^1[3-9]\d{9}$/
  code: string;    // | 必填 | 6 位数字，正则：/^\d{6}$/
}

interface PhoneLoginRes {
  accessToken: string;   // JWT，有效期 7 天
  refreshToken: string;  // 有效期 30 天
  expiresIn: number;     // 过期时间戳
  user: {
    id: string;
    phone: string;
    avatar?: string;
    nickname?: string;
  };
}
```

### 5.3 状态与数据流

- **全局状态：**
  - `authStore.token`：登录态（跨页面共享）
  - `authStore.user`：用户信息
- **本地状态：**
  - `phone`：手机号输入值
  - `code`：验证码输入值
  - `countdown`：倒计时剩余秒数
  - `captchaVisible`：图形验证码弹窗显隐
  - `errorCount`：验证码错误次数
- **缓存策略：**
  - 登录态：localStorage 持久化，自动续期
  - 图形验证码 token：session 级别，验证通过后丢弃

### 5.5 异常场景与兜底策略（Exception Handling）

| 场景编号 | 异常场景 | 触发条件 | 用户感知 | 兜底策略 | 重试/恢复机制 |
|----------|----------|----------|----------|----------|--------------|
| EX-01 | 网络中断 | 获取验证码/登录时断网 | Toast：网络异常，请检查网络 | 按钮恢复可点击，保留输入数据 | 用户可手动重试 |
| EX-02 | 服务端繁忙 | HTTP 503 / 超时 | Toast：系统繁忙，请稍后重试 | 展示友好错误页，提供"重试"按钮 | 自动重试 2 次（指数退避），后转手动 |
| EX-03 | 验证码错误 | 输入错误验证码 | Toast：验证码错误或已过期，清空输入框 | 错误次数 +1，≥3 次触发图形验证码 | 可重新输入 |
| EX-04 | 手机号未注册 | 登录时手机号未注册 | Modal：该手机号未注册，是否立即注册？ | 提供跳转注册入口 | 引导注册流程 |
| EX-05 | 验证码发送频繁 | 60 秒内重复点击 | 按钮保持禁用，Toast：请 X 秒后重试 | 前端倒计时拦截，不重复请求 | 等待倒计时结束 |
| EX-06 | 图形验证码错误 | 用户输错图形验证码 | 输入框标红，提示"图形验证码错误" | 刷新验证码图片，保留已填内容 | 可重新输入 |
| EX-07 | 登录态过期 | 自动续期失败 | 静默跳转登录页，保留原目标路由 | 记录 redirect 参数，登录后自动跳转 | 重新登录 |

## 7. 任务拆分与并行计划（Task Breakdown）

### 7.1 拆分原则

- **按边界拆分**：每个任务有明确的输入输出边界，不互相侵入内部实现
- **按依赖分层**：先开发被依赖的底层（类型、工具、API），再开发上层（页面、组件）
- **2-3 个 Agent 并行**：将任务聚合成 2-3 个"模块包"，每个包内部高内聚，包之间通过契约交互

## 8. 验收标准（Acceptance Criteria）

- [ ] **AC1:** Given 用户输入非法手机号（如 123），When 失去焦点时，Then 输入框边框变红并提示"请输入正确的手机号"
- [ ] **AC2:** Given 用户点击"获取验证码"，When 请求成功后，Then 按钮进入 60 秒倒计时且不可点击
- [ ] **AC3:** Given 用户输入错误验证码，When 点击登录时，Then 提示"验证码错误或已过期"且验证码输入框自动清空
- [ ] **AC4:** Given 用户连续 3 次输入错误验证码，When 再次点击登录时，Then 弹出图形验证码弹窗，校验通过后才可继续
- [ ] **AC5:** Given 用户提交登录时断网，When 点击登录，Then Toast 提示"网络异常"且表单数据保留，恢复网络后可再次提交
- [ ] **AC6:** Given 用户登录成功，When 进入首页后，Then 7 天内免登录，自动续期 token

## 9. 验收注意点与重点场景（Acceptance Checklist）

### 9.1 必验场景（Must Verify）

> 以下场景验收时必须逐一操作验证，不可仅通过代码审查代替。

| 优先级 | 场景 | 验证方式 | 通过标准 |
|--------|------|----------|----------|
| 🔴 P0 | 正常登录流程 | 手动操作 | 输入合法手机号 → 获取验证码 → 输入正确验证码 → 登录成功 → 跳转首页 |
| 🔴 P0 | 验证码倒计时 | 手动操作 | 点击获取验证码后，按钮 60s 内不可点击，倒计时结束恢复 |
| 🔴 P0 | 图形验证码触发 | 手动操作 | 连续输错 3 次验证码后，第 4 次自动弹出图形验证码弹窗 |
| 🟡 P1 | 网络中断兜底 | 断网模拟 | 获取验证码/登录时断网，Toast 提示，数据不丢失，恢复后可重试 |
| 🟡 P1 | 手机号未注册引导 | Mock 数据 | 未注册手机号登录时，Modal 提示引导注册 |
| 🟡 P1 | 登录态续期 | 等待/篡改 token | token 过期前自动静默续期，用户无感知 |
| 🟢 P2 | 多浏览器兼容 | Chrome/Firefox/Safari | 功能正常，样式一致 |
| 🟢 P2 | 埋点数据上报 | 查看埋点平台 | 所有埋点事件触发正确，参数完整 |

### 9.2 易遗漏场景（Easy to Miss）

> 以下场景开发时容易忽略，验收时需重点抽查。

| 风险点 | 为什么容易漏 | 验收方法 |
|--------|--------------|----------|
| 倒计时页面切换 | 切换到其他页面再回来，倒计时状态丢失 | 获取验证码后切换路由，返回后倒计时继续 |
| 验证码快速重发 | 60s 内快速点击获取验证码按钮 | 验证前端拦截，不会重复发送请求 |
| 图形验证码刷新 | 用户看不清要求换一张 | 验证刷新按钮可点击，图片更新 |
| 登录按钮防抖 | 快速双击登录按钮 | 验证只发送一次请求，按钮保持 loading |
| 登录成功回退 | 登录成功后点击浏览器后退 | 验证不回到登录页，或自动跳转到首页 |
| 手机号格式粘贴 | 从别处复制带空格的手机号粘贴 | 验证自动去除空格后正确校验 |
| 验证码自动填充 | 浏览器/系统短信自动填充验证码 | 验证自动填充后登录按钮可用 |

### 9.3 回归检查（Regression Check）

> 本次改动可能影响的其他功能，验收时需确认无回归。

| 影响面 | 检查项 | 验证方式 |
|--------|--------|----------|
| 账号密码登录 | 原有登录方式是否正常 | 进入 `/login/password`，验证功能完好 |
| 现有弹窗组件 | BaseModal 扩展后是否影响其他页面 | 随机抽查 2-3 个现有弹窗 |
| 路由权限 | 新增 `/login/phone` 是否同步到权限系统 | 检查权限配置表 |
| 登录态存储 | 新登录方式是否覆盖/破坏原有登录态 | 先账号密码登录，再手机号登录，验证状态正确 |

- 技术风险：短信验证码到达率受运营商影响，需监控和备用方案
