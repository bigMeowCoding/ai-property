## 8. 任务拆分与并行计划（Task Breakdown）

### 8.1 拆分原则

- **契约先行**：Props 接口和类型定义必须先冻结，所有 Agent 基于此开发
- **渲染与逻辑分离**：一个 Agent 负责 UI 渲染，一个负责交互逻辑/Hook，一个负责文档和测试
- **扩展点预留**：核心渲染完成后，扩展能力可并行开发

### 8.2 任务卡片（Task Cards）

#### 模块 A：契约与基础渲染（Agent-1 负责）

| 任务 ID | 任务名称 | 类型 | 输入 | 输出 | 依赖 | 验收点 |
|---------|----------|------|------|------|------|--------|
| T-A1 | Props 类型与接口定义 | types | Spec 接口设计 | `types.ts` 冻结版本 | 无 | 类型覆盖所有 Props、Events、Slots |
| T-A2 | 核心渲染逻辑 | core | 类型定义 + 设计稿 | 基础渲染（无交互） | T-A1 | 传入基础 Props 正确渲染 |
| T-A3 | 空状态与加载态 | core | 设计稿 | Empty / Loading 组件 | T-A2 | 空数据、加载中、错误态 UI 正确 |

> **模块 A 交付物：** 类型定义 + 基础渲染组件（可独立运行）  
> **并行条件：** T-A1 完成后，模块 B 和 C 可同时启动

---

#### 模块 B：交互与扩展能力（Agent-2 负责）

| 任务 ID | 任务名称 | 类型 | 输入 | 输出 | 依赖 | 验收点 |
|---------|----------|------|------|------|------|--------|
| T-B1 | 交互功能 A | feature | 模块 A 核心渲染 | | T-A2 | |
| T-B2 | 交互功能 B | feature | 模块 A 核心渲染 | | T-A2 | |

> **模块 B 交付物：** 所有交互功能  
> **并行条件：** 依赖模块 A 的 T-A2 完成后启动，与模块 C 并行

---

#### 模块 C：文档、测试与工程化（Agent-3 负责）

| 任务 ID | 任务名称 | 类型 | 输入 | 输出 | 依赖 | 验收点 |
|---------|----------|------|------|------|------|--------|
| T-C1 | 组件单元测试 | test | 模块 A + B 的全部功能 | 测试文件（覆盖率 ≥ 85%） | T-A2, T-B1~B2 | 所有 Props 组合有渲染快照，交互有事件测试 |
| T-C2 | 使用文档 + 场景示例 | docs | 所有使用示例 | README / 文档站 | T-A1~A3, T-B1~B2 | 覆盖基础/高级/扩展点用法，含代码片段 |
| T-C3 | 样式主题与变量 | style | 设计规范 | CSS 变量 / Theme 配置 | T-A2 | 支持主题切换，样式不侵入业务 |

## 9. 验收注意点与重点场景（Acceptance Checklist）

### 9.1 必验场景（Must Verify）

| 优先级 | 场景 | 验证方式 | 通过标准 |
|--------|------|----------|----------|
| 🔴 P0 | 组件在场景 A 零改动接入 | 实际接入业务 A | 传入配置即可渲染，无报错 |
| 🔴 P0 | 组件在场景 B 通过配置满足需求 | 实际接入业务 B | 不 fork 代码，仅通过 Props 配置 |
| 🔴 P0 | 所有交互功能正常 | 手动操作 | |
| 🟡 P1 | 大数据量性能 | 大量数据测试 | 无卡顿，滚动流畅 |
| 🟡 P1 | 主题切换 | 切换 Design Token | 组件样式跟随主题变化 |
| 🟢 P2 | 文档示例可运行 | 复制文档代码到项目 | 直接可用，无额外配置 |

### 9.2 易遗漏场景（Easy to Miss）

| 风险点 | 为什么容易漏 | 验收方法 |
|--------|--------------|----------|
| 受控/非受控模式 | 只测了一种模式 | 验证 value + onChange 和 defaultValue 两种模式 |
| 动态配置 | 运行时修改配置 | 验证增删改后组件正确更新 |
| 键盘无障碍 | 只测了鼠标操作 | Tab 切换焦点，Enter 触发 |
| 响应式适配 | 只在桌面端测试 | 缩小窗口，验证自适应 |
| 内存泄漏 | 大数据量频繁更新 | 长时间运行后检查内存占用 |

### 9.3 回归检查（Regression Check）

| 影响面 | 检查项 | 验证方式 |
|--------|--------|----------|
| 现有组件 | 升级后现有页面是否正常 | 随机抽查 2-3 个现有页面 |
| 主题系统 | 新组件样式是否破坏全局主题 | 检查 Design Token 覆盖范围 |
| 包体积 | 新增组件是否显著增加产物体积 | 对比构建产物体积 |
