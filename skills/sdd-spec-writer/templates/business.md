## 7. 任务拆分与并行计划（Task Breakdown）

### 7.1 拆分原则

- **按边界拆分**：每个任务有明确的输入输出边界，不互相侵入内部实现
- **按依赖分层**：先开发被依赖的底层（类型、工具、API），再开发上层（页面、组件）
- **2-3 个 Agent 并行**：将任务聚合成 2-3 个"模块包"，每个包内部高内聚，包之间通过契约交互

### 7.2 任务卡片（Task Cards）

#### 模块 A：基础层（Agent-1 负责）

| 任务 ID | 任务名称 | 类型 | 输入 | 输出 | 依赖 | 验收点 |

| T-A1 | | types | | | 无 | |
| T-A2 | | service | | | T-A1 | |

> **模块 A 交付物：** 类型定义 + API 层 + 工具方法 + 常量映射  
> **并行条件：** 模块 A 完成后，模块 B 和 C 可同时启动
