# Spring Data JPA

让数据库约束、领域不变量和查询行为相互印证，不依赖 JPA 默认值碰运气。

## 工作流

1. 读取领域规则、现有表结构、Flyway、实体、Repository 和调用方。
2. 为每个不变量决定归属：领域校验、数据库约束，或两者同时。
3. 先定义查询的资源归属和数据量，再选择派生查询、JPQL、投影或原生 SQL。
4. 使用与生产一致的数据库做集成测试，并观察 SQL 数量、锁和事务结果。

## 建模规则

- ID 类型服从项目契约；不要擅自把 Long 改成 UUID，或反向修改。
- 枚举使用字符串持久化，并由数据库约束或测试防止非法值。
- 关联默认惰性加载；集合在实体内初始化，双向关系由行为方法同时维护。
- 避免公开无约束 Setter；通过有业务含义的方法改变状态。
- 时间戳、长度、可空性和唯一性必须与 Flyway 定义一致。
- 跨项目引用同时校验父资源归属，不能把“ID 存在”当成“允许访问”。

## 查询与性能

- 列表接口必须限制结果规模；根据访问模式使用分页或游标。
- 避免在循环中触发懒加载；按用例选择 fetch join、EntityGraph 或只读 projection。
- 查询只取所需字段；批量操作前检查 flush、一级缓存增长和 JDBC batching 条件。
- 先用执行计划或可复现 SQL 证据确认热点，再增加索引。
- 唯一约束是并发一致性的最后防线；应用预检查不能替代数据库约束。

## DevLoop 风险提示

- 每个项目每种文档类型最多一个当前文档，必须有数据库唯一性保障。
- Tasks 的来源 Spec 必须存在、属于同一项目且仍为当前 Spec。
- 所有消息和文档查询必须携带 projectId 或经项目聚合访问，避免跨项目读取。
- 删除项目的子资源处理必须与事务和外键策略一致，不能留下孤儿数据。

## 验证

- 使用 MySQL Testcontainers 执行真实 Flyway 与 Repository 测试，不用 H2 代替方言和约束。
- 覆盖唯一性、外键、非法枚举、跨项目引用、级联删除和并发写入。
- 对可能的 N+1 记录查询证据；不要仅凭注解推断没有问题。

## 常见失误

- `FetchType.EAGER` 掩盖查询设计问题。
- Controller 直接返回 Entity，导致懒加载、字段泄露或序列化循环。
- 只在 Service 做 `exists` 检查，没有数据库唯一约束。
- 测试使用 H2 通过，但 MySQL DDL、索引或锁语义失败。
- Repository 提供无项目范围的 `findById` 给项目子资源接口直接使用。
