## 规则优先级

1. 用户明确需求与验收条件。
2. [项目宪法](./CONSTITUTION.md)中的不可协商约束。
3. 本文件的仓库工作流、技术栈与项目形态规则。
4. 相邻目录中更具体的 `AGENTS.md`。

遇到冲突时说明冲突和影响，不得静默选择方便实现的一方。

## 修改前必做

1. 检查工作区状态并保留用户已有改动。
2. 读取需求 spec、相关入口、调用链、测试与配置，确认当前可观察行为。
3. 用一句话定义本次行为变化：触发条件、旧行为、目标行为。
4. 确定最小验证集；缺陷修复优先建立可失败的复现。
5. 新增依赖、改公共接口、改数据模型或执行迁移前先说明影响。

## 实施与验证

- 保持最小、聚焦的 diff；功能变化与纯重构尽量分开。
- 先在最自然的调用者层级验证，再递归补足边界、错误、权限、并发和清理路径。
- 错误必须保留原因与上下文；禁止吞错、伪造成功或只写日志后继续。
- 完成前检查最终 diff、调试残留、生成文件、敏感信息和文档同步。
- 交接必须列出行为变化、改动文件、实际运行的验证、未验证项与剩余风险。
