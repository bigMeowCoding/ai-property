# 项目开发宪法

Version: 1.0 | Ratified: {{DATE}} | Stack: {{STACK}} | Project type: {{PROJECT_TYPE}}

本宪法规定 **{{PROJECT_NAME}}** 不可协商的工程原则。技术方案、代码实现和评审必须进行合宪性检查。

## 第一条：行为有据可验

- 每项变更必须对应明确需求、缺陷证据或验收条件。
- 缺陷修复必须证明测试能在旧行为上失败、在新行为上通过，或说明无法自动化的原因。
- 未实际运行的验证不得表述为通过；未覆盖风险必须显式交接。

## 第二条：简单且边界清晰

- 只实现当前范围，不为假想复用引入抽象、依赖或基础设施。
- 复用现有模块边界；跨边界依赖必须有单一方向和清晰接口。
- 公共接口、持久化格式和依赖变更必须评估兼容性与回滚路径。

## 第三条：失败必须显式

- 外部输入在信任边界校验；错误保留根因、上下文和可操作反馈。
- 禁止吞错、静默降级为错误数据、泄露凭据或记录敏感载荷。
- 超时、取消、重试、幂等与资源清理按真实失败模式设计。

## 第四条：变更可审查、可恢复

- 保持最小 diff，保护用户已有修改，不执行未经授权的破坏性操作。
- 高风险变更必须提供迁移、灰度或回滚方案。
- 代码、测试、配置、接口文档和 spec 必须在同一变更中保持一致。

## 治理

本宪法高于 `.ai/AGENTS.md` 的普通工作流约定。修订宪法必须记录理由、影响、版本和日期；临时会话不得静默削弱条款。
