## 核心原则

- 重构是在不改变软件可观察行为的前提下，通过一系列微小步骤改进程序内部结构。
- 设计不是在一开始完成的，而是在整个开发过程中逐渐浮现。
- 重构需要 **自测试代码** 作为安全网。
- **两顶帽子**：添加新功能和重构应明确区分，不要同时做两件事。
- 重构可能短期内降低性能，但良好结构使后续性能调优更容易。通常先重构、再调优。
- 重构不是为了“漂亮的代码”，而是为了更快地开发、更少地修复 bug，是纯粹的经济考量。

## 何时重构

- **预备性重构**：添加新功能前清理周边代码，让新功能更容易加入。
- **帮助理解的重构**：阅读代码时用改名、提炼函数等手法验证理解；只要结构更清楚且测试保持绿灯，就可以保留改动。
- **捡垃圾式重构**：顺手修复看到的坏味道，每次改动要小。
- **有计划的重构**：团队安排专门时间偿还技术债务，应控制在合理范围内。
- **不需要修改的丑陋代码可以容忍**——如果它运行良好且不需要触碰，不必为了重构而重构。

## 何时不要继续扩大重构

- 没有可靠基线，且变更涉及公共 API、持久化数据、权限、并发时序或外部副作用。
- 当前测试为红灯，尚未区分既有失败与本次回归。
- 目标已经从局部结构改善膨胀为架构迁移、数据迁移或功能重写。
- 无法说明重构将降低哪一种现实修改成本，只剩审美动机。
- diff 已混入功能、格式化、依赖升级等多类变化，无法独立验证和回滚。

此时先缩小范围、补特征测试、拆分提交或明确转为独立设计任务。

## 重构前的检查清单

- [ ] 是否有可靠的测试覆盖？没有则先补测试或缩小重构范围。
- [ ] 是否区分了“添加功能”和“重构”两顶帽子？
- [ ] 是否从最小、最安全的一步开始？
- [ ] 是否能频繁运行测试并获得反馈？
- [ ] 是否了解代码所有权和依赖边界？
- [ ] 是否记录了公共接口、数据格式、外部副作用和性能基线？
- [ ] 是否能用一句话描述当前坏味道与选择该手法的原因？

| 过长函数 | 提炼函数、引入参数对象、提炼类 |
| 过长参数列表 | 引入参数对象、保持对象完整 |
| 全局数据 | 封装变量 |
| 可变数据 | 封装变量、拆分变量、函数组合成类 |
| 发散式变化 | 拆分阶段、提炼类 |
| 霰弹式修改 | 搬移函数、搬移字段、函数组合成类 |
| 依恋情结 | 搬移函数 |

| 循环 | 以管道取代循环 |
| 冗赘的元素 | 内联函数、内联类 |
| 夸夸其谈通用性 | 折叠继承体系、内联函数、移除死代码 |
| 临时字段 | 引入特例、提炼类 |
| 过长的消息链 | 隐藏委托关系 |

| 注释解释糟糕代码 | 提炼函数、引入断言 |

## 常见重构路径

遇到复杂情况时，通常不是只用一个手法，而是按一定顺序组合使用：

### 路径 A：整理一个过长函数

1. **变量改名**：把含义不清的局部变量改成有意义的名字。
2. **提炼变量**：把复杂表达式拆成命名良好的临时变量。
3. **提炼函数**：把独立逻辑块提取成函数，用函数名解释意图。
4. **引入参数对象**：如果多个参数总是一起出现，封装成对象。
5. **拆分阶段**：如果函数在不同阶段做不同事，拆成多个函数或类。

每一步后运行最小相关测试；不要先完成整条路径再验证。

### 路径 B：消除重复代码

1. **搬移语句**：把相似代码聚拢到同一位置。
2. **提炼函数**：提取相同逻辑。
3. **函数参数化**：如果重复代码只有少量差异，用参数统一。
4. **搬移函数**：把函数放到最合适的类或模块中。
5. **提炼超类 / 提炼类**：如果重复跨越多个类，考虑抽象共性。

### 路径 C：简化复杂条件

1. **分解条件表达式**：把复杂 if-else 拆成多个小函数。
2. **以卫语句取代嵌套条件表达式**：先处理边缘情况，减少嵌套。
3. **合并条件表达式**：如果多个条件导致同一结果，合并它们。
4. **以多态取代条件表达式**：如果条件随类型变化，考虑引入子类或策略。
5. **引入特例**：如果 null 或特殊值到处检查，创建特例对象。

### 路径 D：改善数据组织

1. **拆分变量**：一个变量被多次赋值表示不同含义时，拆成多个变量。
2. **以查询取代派生变量**：如果变量可由其他数据计算得出，用查询替代。
3. **以对象取代基本类型**：当基本类型开始携带行为或被多处解释时。
4. **将引用对象改为值对象**：如果对象应不可变且按值比较。
5. **封装记录 / 封装集合**：控制数据访问和修改入口。

## 重构手法选择指南

### 函数级别

| 问题 | 首选手法 | 说明 |
|------|---------|------|
| 函数做太多事 | 提炼函数 | 每个函数只做一件事，用函数名表达意图 |
| 函数名不准确 | 改变函数声明 | 好名字是清晰代码的基石 |
| 函数参数太多 | 引入参数对象 / 保持对象完整 | 把相关参数封装起来 |
| 函数被过度包装 | 内联函数 | 如果函数只是简单转发，去掉中间层 |
| 查询和修改混在一起 | 将查询函数和修改函数分离 | 一个函数要么返回值，要么产生副作用 |

### 数据级别

| 问题 | 首选手法 | 说明 |
|------|---------|------|
| 全局变量被到处修改 | 封装变量 | 控制访问入口，便于后续改造 |
| 一个变量多种含义 | 拆分变量 | 每个变量只表示一种含义 |
| 多个数据项总是一起出现 | 引入参数对象 / 提炼类 | 把它们封装成有意义的整体 |
| 过度使用字符串/数字 | 以对象取代基本类型 | 让类型携带行为和约束 |
| 派生状态与源状态不同步 | 以查询取代派生变量 | 减少状态不一致的风险 |

### 类/模块级别

| 问题 | 首选手法 | 说明 |
|------|---------|------|
| 类太大 | 提炼类 | 把相关字段和函数拆到新类 |
| 函数对另一个类更感兴趣 | 搬移函数 | 把函数放到它应该属于的类 |
| 继承体系被滥用 | 以委托取代子类 / 超类 | 组合优于继承 |
| 子类只使用部分父类接口 | 以委托取代超类 | 避免被拒绝的遗赠 |
| 多个类有相同行为 | 提炼超类 / 提炼类 | 抽象共性，消除重复 |

## 重构名录（按章分组）

### 第一组重构（最常用）

- **提炼函数 / 内联函数**：拆分/合并函数。
- **提炼变量 / 内联变量**：给表达式命名/去除不必要的变量。
- **改变函数声明**：改名、改参数列表，使函数意图更清晰。
- **封装变量**：限制数据访问入口。
- **变量改名**：改善命名可读性。
- **引入参数对象**：把相关参数封装成对象。
- **函数组合成类 / 变换**：把相关计算组织成类或数据变换。
- **拆分阶段**：把处理过程拆分为独立阶段。

### 封装

- **封装记录 / 集合**：控制数据结构访问。
- **以对象取代基本类型**：为基本类型增加行为和语义。
- **以查询取代临时变量**：用函数替代重复计算的临时变量。
- **提炼类 / 内联类**：拆分/合并类。
- **隐藏委托关系 / 移除中间人**：调整对象间的委托层次。
- **替换算法**：用更清晰或更高效的算法替换旧算法。

### 搬移特性

- **搬移函数 / 字段**：把代码放到最合适的类。
- **搬移语句到函数 / 调用者**：调整函数边界。
- **以函数调用取代内联代码**：消除重复内联逻辑。
- **移动语句**：调整语句顺序使逻辑更清晰。
- **拆分循环**：一个循环只做一件事。
- **以管道取代循环**：用 map/filter/reduce 替代显式循环。
- **移除死代码**：删除不再使用的代码。

### 重新组织数据

- **拆分变量**：一个变量只表示一种含义。
- **字段改名**：改善字段命名。
- **以查询取代派生变量**：减少派生状态。
- **将引用对象改为值对象 / 反之**：根据可变性需求调整。

### 简化条件逻辑

- **分解条件表达式**：把复杂条件拆成命名函数。
- **合并条件表达式**：合并导致相同结果的条件。
- **以卫语句取代嵌套条件表达式**：用提前返回减少嵌套。
- **以多态取代条件表达式**：用类型系统替代 switch/if-else。
- **引入特例**：为特殊情况创建对象，避免到处检查 null。
- **引入断言**：明确表达假设。

### 重构 API

- **将查询函数和修改函数分离**：命令与查询分离。
- **函数参数化**：合并相似函数。
- **移除标记参数**：避免布尔/枚举参数控制行为。
- **保持对象完整**：传递整个对象而不是多个字段。
- **以查询取代参数 / 反之**：调整参数与查询的边界。
- **移除设值函数**：减少可变状态。
- **以工厂函数取代构造函数**：增加构造灵活性。
- **以命令取代函数 / 反之**：在简单函数和命令对象之间取舍。

### 处理继承关系

- **函数/字段上移或下移**：在继承层次间调整代码位置。
- **构造函数本体上移**：提取共同构造逻辑。
- **以子类取代类型码**：用多态替代类型码。
- **移除子类**：当子类不再必要时内联。
- **提炼超类**：抽象共同父类。
- **折叠继承体系**：合并不再必要的继承层次。
- **以委托取代子类 / 超类**：用组合替代继承。

## 重构安全网

- **自测试代码**：重构前确保有测试；每步重构后运行测试。
- **特征测试**：遗留代码缺少测试时，先记录当前可观察行为，不把“理想行为”混入重构基线。
- **自动化重构**：优先使用 IDE 提供的自动化重构，减少手误。
- **小步前进**：每个步骤都要小到“错了也能立即撤销”。
- **持续集成**：频繁集成，减少分支间语义冲突。
- **版本控制**：在清晰节点提交，便于回滚。
- **差异审查**：确认没有意外改变公共接口、序列化键、调用顺序、错误语义和副作用。
