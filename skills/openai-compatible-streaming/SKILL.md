# OpenAI 兼容流式调用

隔离业务、供应商协议和下游 SSE，并让失败或取消不会破坏已经确认的数据。

## 必读参考

实现或修改流式链路前读取 [streaming-contract.md](references/streaming-contract.md)。如果仓库已有更具体契约，以仓库契约为准并同步更新测试。

## 工作流

1. 识别配置、消息历史、供应商请求、流片段、持久化和前端消费者的完整数据流。
2. 定义开始、增量、完成、错误与取消的状态机，以及每个阶段允许的数据库写入。
3. 在适配器边界解析供应商事件，转换成内部事件；业务层不依赖供应商 DTO。
4. 用可控 fake server 验证分片、畸形事件、慢响应、超时、断连和重试。

## 核心约束

- API Base URL、Model Name、超时使用类型化配置并启动校验；API Key 加密存储。
- 读取配置只暴露“是否已配置”；日志、异常和 trace 不记录密钥或完整 Authorization。
- 不把数据库事务保持到流结束；用户消息与生成中/完成状态采用短事务更新。
- 只有收到完成语义后才把助手消息标记为完整；部分内容的保留或丢弃策略必须明确。
- 客户端取消向上游传播并释放连接、订阅和缓冲区；取消不伪装成成功完成。
- 重试必须区分“尚未产生输出”和“已经产生可见输出”，避免重复片段与重复消息。
- 限制历史条数、单条长度、总上下文和响应缓冲，防止内存与费用失控。
- 供应商不支持的字段通过能力配置或明确错误处理，不能静默假设兼容。
- 保持项目已选的 Spring Web 技术栈；只有任务明确批准时才引入 WebFlux/Reactor API 或改变应用类型。
- 公共 URL、请求字段、事件字段、默认超时、重试次数、加密算法与数据表字段必须来自现有契约或已确认决策。设计任务可以提出方案，但要逐项标注“建议/待确认”，不能描述为已冻结事实。
- 在声称某实现、迁移或依赖“现有”之前检查实际文件；Spec 和 Task 中的目标设计不等于已实现。

## 验证

- fake server 覆盖正常分片、首片段超时、中途 5xx、畸形 JSON、连接关闭和客户端取消。
- 断言数据库最终状态、连接释放、事件顺序、错误脱敏和重试无重复。
- 测量首片段延迟与完整耗时；没有数据时不声称达到性能目标。

## 常见失误

- 把供应商 chunk 原样透传给前端，导致契约被供应商绑定。
- 在流开始后尝试返回普通 `ResponseEntity` JSON 错误。
- 网络调用包在长事务中，造成连接占用和锁等待。
- 对已经输出的请求自动重试，产生重复文本或重复记录。
- 调试日志打印请求头、配置对象或供应商原始错误体。
