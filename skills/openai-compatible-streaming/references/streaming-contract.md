# 流式链路参考契约

## 内部事件

内部协议至少区分以下语义；具体字段名服从项目共享契约：

| 事件 | 含义 | 终态 |
| --- | --- | --- |
| `start` | 请求已接受并建立生成上下文 | 否 |
| `delta` | 新增且有序的文本片段 | 否 |
| `complete` | 上游正常结束，最终内容可以提交 | 是 |
| `error` | 上游、解析或内部失败，携带安全错误码 | 是 |
| `cancelled` | 客户端或服务端取消并完成资源清理 | 是 |

每个流只能出现一个终态。终态后到达的片段必须忽略并记录不含敏感数据的诊断信息。

## 持久化状态机

```text
用户消息：先独立可靠保存
助手生成：PENDING → STREAMING → COMPLETED
                         ├→ FAILED
                         └→ CANCELLED
```

- 不允许 `FAILED/CANCELLED` 直接转为 `COMPLETED`。
- 重试创建明确的新 attempt，或使用能证明无重复的同一 attempt 版本条件更新。
- 文档生成与普通澄清消息如果持久化规则不同，分别定义，不共享含糊的“成功”标志。

## 超时与重试

- 分别配置连接超时、首片段超时、片段空闲超时和总时长上限。
- 仅对明确可重试的网络错误或 429/部分 5xx 重试，并采用有上限的退避。
- 一旦向客户端发出可见 `delta`，默认不自动重放整个请求；返回可识别错误，让调用方显式重试。
- 连接测试使用独立短超时，不复用正式生成的长超时。

## 安全与资源

- 对 URL 限制协议并按部署策略防止访问不可信内网地址。
- 请求与响应日志采用字段白名单；密钥、Authorization、Cookie 和完整提示默认不记录。
- 设置 HTTP 连接池、并发上限、单项目生成保护和缓冲区上限。
- 在正常、错误、超时和取消路径统一关闭响应体、订阅与 emitter。

## 测试场景

1. 多个 `delta` 后正常完成，顺序和最终内容一致。
2. 首片段超时，没有助手完成记录。
3. 若干 `delta` 后断流，只有一个错误终态且不自动重复输出。
4. 客户端取消，上游连接关闭，既有项目、用户消息和文档不受损。
5. 同项目并发发起，第二个请求被拒绝或按既定策略串行化。
6. 供应商错误体包含测试密钥，日志和响应仍完成脱敏。
