# Spring 测试策略

从最自然的调用者入口证明业务价值，再向低层递归覆盖仍可能失败的职责。

## 工作流

1. 读取需求验收、现有测试配置、fixture 和实际构建命令。
2. 为核心价值流画最小测试树，先选择能证明行为的最高性价比入口。
3. 对每个测试追问“即使通过，什么仍可能失败”，把分支、边界和状态下沉。
4. 运行最小相关子树，再按风险扩大到模块和完整构建。

## 测试层级

- **纯单元测试**：领域状态机、校验、规范化、错误映射；不启动 Spring。
- **Controller 切片**：请求解析、Validation、状态码、JSON/SSE 前置错误；mock 应用用例。
- **JPA/数据库集成**：真实 Flyway、MySQL 约束、查询、锁、事务回滚；使用 Testcontainers。
- **应用集成测试**：Controller、Service、数据库和受控外部适配器协作。
- **端到端/API 主链路**：只保留关键价值流和高代价失败，不枚举全部低层组合。

## 规则

- 测试标题表达“条件 → 行为”；断言输出、错误、状态与副作用，不能只执行代码。
- 在拥有行为的边界外 mock；数据库方言、迁移和事务不能用 H2 或 Repository mock 证明。
- 模型调用使用可控 fake server，禁止依赖真实网络、真实密钥或供应商稳定性。
- 并发测试使用 barrier/latch 等确定性协调，不使用固定 sleep 猜时序。
- 时间、随机数和 ID 在需要确定性时通过端口注入。
- 测试数量服从风险，不使用 70/20/10 等固定配额；覆盖率只用于寻找盲区。
- 根据实际 Spring Boot 版本选择 `@MockitoBean` 或仍受支持的 `@MockBean`，不要凭模板强制升级。

## DevLoop 最小测试树

```text
API 主链路：创建项目 → 对话 → Spec → Tasks → 导出
├── 模型流：完整上下文、首片段、超时、断开、重试无重复
├── 文档状态：覆盖、失效、结构校验、Spec → Tasks 确认顺序
├── 数据约束：项目隔离、当前文档唯一、跨项目来源拒绝、级联删除
└── 安全：密钥加密/脱敏、非法输入、恶意文件名和 ZIP 路径
```

## 停止条件

- 所有 P0/P1 意图空缺已覆盖或被明确接受。
- 测试独立、确定、可读，且失败信息能定位责任边界。
- 真实 MySQL、迁移、事务和上游替身覆盖了不能由单元测试证明的行为。
- 已记录实际执行命令和结果；未运行项不得写成通过。
